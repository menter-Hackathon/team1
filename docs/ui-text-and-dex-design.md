# メニューの文字を減らす・図鑑の詳しい画面（設計）

2026-11-19。対象はメニュー（タイトル・スキャン・能力えらび・図鑑・リザルト・ゲームオーバー）。
**ステージの中（HUD・右上の通知・技の演出）と、感染デスクトップ（`DesktopScreen`。Mac のパロディの文字だけ）は変えない。**

- 座標は全部 **PixelGui の単位（640×360 の画面。実際の画面はその2倍）**。「inner」は `PixelGui.Window` が返す中身の四角。
- 文字の大きさは今と同じ 8（英字）/ 12 / 16 / 24 だけを使う。
- 文は【仮】。意味を変えずに短くしただけなので、企画が直してよい。

## 0. 方針

1. 文（「。」で終わる説明）はメニューから無くす。残すのは **画面の名前・ボタンの動詞・数字・アプリの名前・能力の名前と1行**。
2. 状態は絵で見せる：選択中＝オレンジの縁、まだ＝グレー、使用時間＝メーターと `10h`。
3. 能力は「アイコン＋名前＋1行（12字まで）＋絵のタグ（1〜3個）＋届く所の図」で分かるようにする（2章）。
4. 図鑑で、正常化したアプリを決定すると、ボスの姿と能力の詳しい画面を開く（3章）。

## 3. 図鑑の詳しい画面

### 3-1. 開き方・操作

`AppDexMenu` に「一覧」と「詳しい画面」の2つの状態を持たせる（`_detail`：開いているアプリの番号。-1＝一覧）。

| 操作 | 一覧 | 詳しい画面 |
|---|---|---|
| ← → ↑ ↓（A D W S） | 選ぶアプリを動かす（今のまま） | ← →：前／次の **正常化したアプリ** へ（グレーは飛ばす。端で止まる）。↑ ↓：何もしない |
| Z・Enter・Space | 選んでいるアプリが正常化済みなら、詳しい画面を開く（`ui_decide`）。グレーなら開かない（`ui_cancel` の音と、枠が横に 2 ゆれる 0.15秒） | 一覧へ戻る |
| X・Esc・Backspace | 図鑑を閉じる（今のまま） | **一覧へ戻る**（図鑑は閉じない。`ui_cancel`） |
| クリック | **正常化したアプリをクリックしたら、すぐ詳しい画面を開く**（選ぶのも同時）。グレーのアプリは選ぶだけ | 左上の赤い丸＝一覧へ戻る。`‹` `›` ＝前／次 |

- 詳しい画面を開いたまま `Close()` が呼ばれたとき（外から）は、`_detail = -1` に戻してから閉じる。
- 一覧へ戻ったとき、選んでいるアプリは、最後に見ていたアプリにする。

### 3-4. ボスの姿の作り方

実際のランと同じ決め方で、そのアプリのボスを決める。**`RunState` のステージを作る所（代用ボスを決める部分）から、「アプリの行 → ボスのプレハブ・プロフィール・見た目」を決める所だけを static の関数に切り出し、図鑑とランの両方から呼ぶ**（図鑑だけ別の決め方を書かない）。

| アプリ | プレハブ | 着ているウィンドウ |
|---|---|---|
| 対応表のアプリ（Chrome・VS Code。`AppCatalog.FindByName` / `Find` で当たる） | その行の `BossPrefab` | プレハブの `BossArmorVisual` の `_windowStages[0]`（`BossB_Window_Browser` / `BossB_Window_Editor`）。**専用の絵のまま** |
| ほかのアプリ（代用ボス・キットのボス） | ランと同じ（`FindAppBoss` のプレハブ → カテゴリの合うひな形 → 名前のハッシュ） | `BossWindowArt.Create(AppVisuals.Get(row).Icon24, テーマ, 名前)[0]`（きれいなウィンドウ。アプリごとに1回作って持っておく） |
| Terminal（ラスボス。図鑑に載っていれば） | `AppCatalog.FinalBoss.BossPrefab` | `BossWindowArt.Create`（ランと同じ） |

描き方（OnGUI。プレハブは `Instantiate` しない。プレハブの `BossArmorVisual` から絵を読むだけ）：

- `BossArmorVisual` に読むだけの入口を足す：体・手・顔の `SpriteRenderer`（`sprite` と `transform.localPosition`）、`_windowStages`、`_faceFrames`。
- 重ねる順（後ろから）：体 → ウィンドウ → 手 → 顔（`DemoAppBossVisual` と同じ順：体 10、ウィンドウ 12、手 13、顔 13）。
- 位置：プレハブの中の各絵の `localPosition`（マス）× 18 ドット × 2。`PixelGui.DrawSprite` で、絵の `pivot` を合わせて描く。
- 絵の大きさ：体は `BossB_Body_Stand` / `_Float`（276×80＝92×80 が3コマ）、手は 92×80、顔は 120×12（30×12 が4コマ）、ウィンドウは 48×36。
- 動き（安い分だけ）：体のコマを 0.25秒ごとに送る（体の `Sprite` がコマ送りの配列で読めるとき。読めなければ止め絵）。顔は `_faceFrames[0]`、3秒に1回 0.12秒だけ `[1]`（まばたき）。全体を上下に 2（1ドット分）、2秒の周期でゆらす。
- 読めなかった絵（null）は飛ばす。全部 null のときは、枠の中にアプリのアイコン（24 を4倍）だけを出す。

### 3-5. ボスの技の札

`AttackData` には、画面に出す名前が無い。新しく名前を付けない（約120個ある）ので、**アセットの名前から機械的に作る英字**を出す。アプリのパロディの字として読める。

- 元：決めたプロフィール（対応表の本物のアプリは `OwnProfile` があればそれ）の `Phase1.Moves` ＋ `Phase2.Moves`。移動用の `WarpAttack` は入れない。
- 名前の作り方：アセット名から、末尾の `_P1` `_P2` を取る → **最後の `_` より後ろ**だけを残す → 小文字の次の大文字の前に空白を入れる（数字の後ろでは切らない）。manifest の BOSS の行の全部（約115種類）で確かめた。いちばん長いのは `Error Window Fall`（17字）。
  - 最後の `_` より後ろにするのは、`Attack_Gemini_LongAnswer_Breakpoint` → `Breakpoint`、`Attack_Chrome_Joined_TabMultiply` → `Tab Multiply` のように、途中に `_` がある名前のため。
  - `Attack_Zoom_Gallery_P1` → `Gallery`、`Attack_Zoom_ClapStorm_P2` → `Clap Storm`、`Attack_Chrome_TabShuriken_P1` → `Tab Shuriken`、`Attack_Terminal_RmRf_P1` → `Rm Rf`
- 同じ名前は1つにまとめる（P1 と P2）。順番は第1形態の技 → 第2形態だけの技。**最大4つ**。
- 札：高さ 22。左に `AttackData.Sprite`（16×16、`SlotBg` の枠 20×20 の中。null なら枠の中にアプリの `Icon16`）、右に名前（英字 8、`Ink`）。札の地は `White`、縁は `FrameDark` 1。**第2形態だけの技は、縁を `Magenta`** にする（字は足さない）。
- 幅：札は 3-3 の cw（約 156）で固定。名前は枠の右 4 から、`TextFit`（英字 8 は1字が約 8 なので、16字くらいまで入る。入らない分は「…」）。
- 借り物の技（代用ボスが Chrome／VS Code のひな形の技を使うとき）も、そのまま出す（実際に戦った技なので）。

### 確かめること

- 能力えらび：3枚とも 1行が切れずに1行で出る（いちばん長いのは `当てると5秒ゲージ1.5倍`）。
- 図鑑：グレーのアプリで Z を押しても開かない。詳しい画面で X を押すと一覧へ戻り、もう一度 X で図鑑が閉じる。
- 図鑑の確認は、本物の `app_dex.json` を退避してから（前の決まり）。
- OnGUI の画面は、プレイヤーをビルドして撮る（バッチでは写らない）。
