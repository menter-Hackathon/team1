## 1. なぜ単調か（今の作りを読んで）

| # | 原因 | 今の作り |
|---|---|---|
| 1 | 山と谷がない | `ZakoSpawner` は、時間がたつほど間隔を短く・同時の数を多くするだけ。ずっと右上がりの1本の線で、盛り上がる所もほっとする所もない |
| 2 | 出方がいつも同じ | 1体ずつ、煙と一緒に、床のどこかに出る。歩く7割・撃つ3割。群れ・はさみうち・上から、が無い |
| 3 | 雑魚が2種類だけ | 歩く・撃つ。どちらも1回で倒れる。プレイヤーのやる事が「近づいて1回たたく」から変わらない |
| 4 | 倒した見返りが毎回同じ | 小さい煙と、ゲージが1目盛り。3体まとめて倒しても、10体続けて倒しても、同じ |
| 5 | ステージの中で何も変わらない | 最初の1秒と最後の1秒で、画面が同じ。進んだ手ごたえは右上のゲージだけ |
| 6 | 3ステージの違いが色とアイコンだけ | 代用ボス・Finder・Premiere・Terminal は全部 1画面のステージで、同じ形・同じ雑魚・同じ出方。ステージが進んでも雑魚の時間は変わらない |
| 7 | 空白の時間がある | 画面の雑魚を倒し切っても、次が出るまで最大2.2秒待つ。最後の数体は「出るのを待って、たたく」だけになる |
| 8 | アプリらしさが雑魚の時間に無い | スキン（アプリごとの見た目）はボスの技とプレイヤーの能力にだけ付いている。雑魚の時間は、どのアプリでも同じ出来事 |

- まとめ：**「同じ強さの刺激が、同じ間隔で、最後まで続く」**のが原因。直すのは、数を増やす事ではなく、**場面を分ける事**と、**倒したときの返事を変える事**。

## 2. 1ステージの中の山と谷

### 2-1. 5つの場面

雑魚の時間を、5つの場面に分ける。場面は**時間ではなく、進み具合**（1画面は倒した数、ほかは進んだ距離）で切り替える。プレイヤーの速さに合うので、待たされない。

| 場面 | ねらい（気持ち） | 何が起きる | 緊張 |
|---|---|---|---|
| ① 入り | 肩ならし。「このステージはこの色」 | 最初から置いてある雑魚だけ。新しく出さない | 低 |
| ② 盛り上がり | だんだん忙しくなる | 2〜3体ずつの小さい組で出る。連続で倒しやすい並び | 中 |
| ③ 出来事 | 「何か起きた！」。そのアプリの事件 | アプリごとの出来事（3章）。雑魚は少なめ、撃つ雑魚は出さない | 高 |
| ④ ひと休み | ほっとする。進んだのが見える | 雑魚を出さない。感染のもやが大きく晴れる（6章）。拾える物があれば、ここで拾う | 低 |
| ⑤ 最高潮 | 「あと少し」。まとめて倒して気持ちよく終わる | 群れが2回＋強い雑魚1体。最後の1体でスローになり、ボスへ | 最高 |

- 並びは「低 → 中 → 高 → 低 → 最高」。ひと休みの直後が一番高いので、差が大きく感じる。
- ボス戦の前に一番の山を置き、ボスの登場の1秒（今のまま）を、もう1つの小さい谷として使う。

### 2-2. 1画面のステージ（Stage_Desktop）：倒した数で切り替える

今の仕組み（`ZakoSpawner` のノルマ ＋ `EnemyWave` ＋ 右上のゲージ）をそのまま使う。ノルマの数だけを変える。

- 例：2ステージ目（合わせて 20体【仮】）

| 場面 | ゲージ | 雑魚 | 秒の目安 | 出し方（間隔・同時の数） |
|---|---|---|---|---|
| ① 入り | 0〜20% | 4体（最初の4体） | 8 | 出さない |
| ② 盛り上がり | 20〜45% | 5体（2体＋3体） | 10 | 1.4秒・同時に4 |
| ③ 出来事 | 45〜65% | 4体 | 10〜12 | 2.5秒・同時に2。撃つ雑魚なし |
| ④ ひと休み | 65% で止まる | 0体 | 3〜4 | 出さない |
| ⑤ 最高潮 | 65〜100% | 7体（群れ3＋群れ3＋強い雑魚1） | 12 | 群れは 0.25秒おきに連続で出す・同時に7 |
| 合わせて | | 20体 | 約45 | |

- **ゲージ**：ステージが始まったときに、全部の数（20）を `EnemyWave.Expect` に入れておく。出来事・群れ・強い雑魚も、全部この数の中。だからゲージは戻らないし、途中で伸びない。
  - 強い雑魚は1体として数える。
  - 「一掃」（4-1）で倒した雑魚も数える。
- **場面の切り替え**：場面ごとに「出す数」（予算。2-3 の表）を持つ。**その場面の予算を出し終えて、全員倒したら次の場面へ**。表のゲージの値は、その結果。
  - だから、場面の変わり目では画面に雑魚がいない（ひと休みに、残りの雑魚が持ち越されない）。
  - ③は「予算を倒し切った」と「出来事が終わった（8〜12秒）」の両方で終わる。予算が先に無くなったら、危ない物だけの時間になる。出来事が先に終わったら、残りを②の出し方で出す。
  - ④は、③が終わってから 3秒【仮】。
- **空白をなくす**：②③⑤で、画面の雑魚が 0体になったら、間隔を待たずに 0.3秒で次を出す。
- **出す場所**
  - 組・群れは、プレイヤーから遠い方の画面の端の近くに、0.8マスずつ並べて出す（歩いてくる列になる。まとめて倒しやすい）。
  - 最高潮の2回目の群れは、反対の端から（はさみうち）。
  - プレイヤーの4マス以内には出さない（今のまま）。

### 2-4. 横スクロール（Chrome）・ウィンドウ移動（VS Code）：進んだ所で切り替える

この2つは、今は雑魚を倒さなくてもボス部屋に入れる（`BossRoomGate` はプレイヤーの x で動く）。この決まりは変えない。場面は、**一番右まで進んだ x** で切り替える。

- 進み具合 ＝ 一番右まで進んだ x ÷ ボス部屋の入口の x。感染のもや（6章）もこの値で晴れる。
- 横スクロール（長さ 95マス）

| 場面 | 進み具合 | 何が起きる |
|---|---|---|
| ① 入り | 0〜20% | 置いてある雑魚だけ |
| ② 盛り上がり | 20〜45% | 2〜3体の組が前から。今ある穴・消える足場・降ってくる通知はそのまま |
| ③ 出来事 | 45〜65% | 区間に入ると始まる。区間を出るか 12秒で終わる |
| ④ ひと休み | 65〜75% | 雑魚を出さない。拾える物を1つ置く（優先度B） |
| ⑤ 最高潮 | 75〜100% | 前から群れ、少し遅れて後ろから群れ。強い雑魚1体 |

- ウィンドウ移動（部屋3つ）：部屋1＝①②、部屋2＝③（部屋に入って 1.5秒後に始まる）、部屋3 に入って最初の 3秒＝④、部屋3 の残り＝⑤。

- 最高潮を走り抜けられるのは、今の決まりのまま。扉の前の群れを倒さないと入れない形にするかは【要相談③】。

## 3. 出来事（アプリごとの事件）

### 3-1. 考え方

- 動きは**3つの型**だけ作る。アプリごとの違いは「どの型か」と「スキンの絵」と「隅の通知の短い文字」で出す。13個の専用の出来事は作らない。
- 絵は、今のスキンの仕組みにそのまま乗せる：
  - 出来事用の `AttackRunner` を1つ用意し、`Skin`・`SkinTheme`・`SkinIcon` に、そのステージのアプリの物を入れる（`StageDirector` がボスに入れているのと同じ値）。
  - その `AttackRunner` から、今ある部品 `FallingObject.Spawn`・`AreaStrike.Spawn` を呼ぶ。部品が `SkinDresser.Dress` を呼ぶので、そのアプリの絵が付く。**スキンのファイルは変えない。**
  - 攻撃データの名前で枠が決まる（`SkinTables.FrameOf`）。名前に `ErrorWindowFall` を入れると落下物、`Breakpoint` を入れると柱、`RedWave` を入れると床の枠になる。`Attack_Stage_` で始めると枠が付かないので、**`Attack_Pace_ErrorWindowFall` のような名前**にする。
  - スキンにその枠の絵が無ければ、Generic の絵、それも無ければ攻撃データの絵になる（今の仕組みのまま）。
- 始まり方（どの型も同じ。文字の説明はしない）
  1. 画面のふちが 0.3秒赤く光る（`ScreenFx.EdgeRed`）。
  2. 右上の隅に通知が出る（`CornerToast.Show`。アプリのアイコン＋下の表の短い文字。飾り）。
  3. 0.8秒後に最初の危ない物の予告が出る。
- 終わり方：危ない物をすべて消し、白い光を 0.06秒（`ScreenFx.WhiteFlash`）。そのまま④ひと休みへ。

### 3-2. 3つの型

| 型 | 動き | 使う部品 | プレイヤーのやる事 |
|---|---|---|---|
| 雨 | 画面の上から物が次々に落ちる。落ちる床に影（予告 0.8秒）。0.7秒おき、プレイヤーの近く±3マス。同時に3個まで | `FallingObject.Spawn`（`NotificationDropper` と同じ呼び方） | 影を見て動きながら、雑魚を倒す |
| 柱・床 | 床の半分（左か右）に、予告 1.0秒 → 0.6秒だけ判定。左右を交互に3〜4回。すり抜け床（フォルダ）の上は当たらない | `AreaStrike.Spawn` | 安全な側か足場へ動く。場所を変えさせる |
| 群れ | 危ない物は出ない。小さい雑魚（速い・0.8倍の大きさ）が、一方の端から 7〜9体の列で流れ込む。ゲージに数える（③の予算＋上乗せ。2-3） | `ZakoSpawner`（10-2 の `SpawnNow`） | まとめて倒す。連続キルのごほうびの場面 |

- 「群れ」の型のアプリは、緊張より爽快の出来事になる。それでよい（アプリごとに気分が変わる）。

### 3-3. アプリごとの表【仮】

| スキン | 事件 | 型 | 隅の通知の文字（飾り） |
|---|---|---|---|
| Browser（Chrome・Safari） | タブを開きすぎた | 群れ（画面の上のタブの列から、1体ずつ落ちてくる） | Too many tabs |

## 4. 見返り（倒したときの気持ちよさ・拾える物）

### 4-1. 連続キル（チェイン）

- 雑魚を倒してから 2.5秒以内に次を倒すと、つながる。切れるのは時間切れだけ（ダメージでは切れない）。
- 見せ方：プレイヤーの頭の上に、小さいバッジ（白いふち・黄色。`x3` のような飾りの数字）。つながるたびにポンとはねる。切れると、しぼんで消える。数字を出してよいかは【要相談⑤】。だめなら、バッジの大きさと色だけで見せる。
- つながるほど、返事が大きくなる。当たったエフェクトは、今は `Hitbox.AnyHit` から自動で出る（`HitFx.OnAnyHit`）。これは変えない。連続キルの部品が、倒れた雑魚の位置で**もう1回 `HitFx.Play` を、強い強さで呼ぶ**（スキンは `StagePacer.Skin` ではなく、プレイヤーの攻撃のスキンが分からないので Generic でよい【仮】）。
  - 同じ相手・同じフレームなら、`HitFx` は強い方だけを出す（今の決まり）。フレームがずれても、上に重なるだけで問題ない。
  - ヒットストップは `HitStop` の「1秒に合計 0.2秒まで」の中に入る（こえた分は出ない）。
  - 数えるのは、場面が `Done` になる前だけ。ボス戦の雑魚・逃げるウイルス本体・ボスは数えない（ボス戦を変えない）。

| つながった数 | 起きる事 |
|---|---|
| 1〜2 | 今のまま（Small） |
| 3〜4 | かけらが増える（Light）。バッジが1段大きくなる |
| 5 | **一掃**：プレイヤーを中心に白い輪が広がり（半径 6マス）、中の雑魚が全部倒れる。ヒットストップ 0.12秒。隅に、そのアプリのとどめの通知の題名（`AppSkin.NotificationTitle`。All read・Build succeeded など） |
| 6以上 | Heavy のまま続く。10 でもう1回、一掃 |

- 一掃は 8秒に1回まで。強い雑魚には 1ダメージ。ボスが出たあとは起きない。
- とどめの通知の題名を雑魚の時間にも使うので、ボスのとどめが薄まらないかは【要相談⑦】。

### 4-2. まとめて倒す

- 1回の攻撃（0.15秒以内）で 2体以上倒したとき：強さを1段上げる・白い光 0.06秒・ヒットストップ 0.08秒（`HitStop.Request`。1秒に合計 0.2秒までの今の決まりの中）。
- 組と群れが列で来るので、能力（弾・柱・爆発）で自然に起きる。「能力を雑魚に使う理由」になる。

### 4-3. 強い雑魚と、拾える物（優先度B）

- **強い雑魚**：歩く雑魚の 1.5倍の大きさ・HP 3・歩く速さは 0.7倍。近接（ダメージ1）なら3回、強い能力（ブレークポイント・ボムの爆発はダメージ3）なら1回で倒れる。能力を使う理由になる。そのステージのアプリのアイコンを小さく抱えている（ボスの子分に見える）。最高潮に1体。
  - 倒すと、Heavy の当たった絵・ヒットストップ・拾える物を1つ落とす。
- **拾える物**（アプリのアイコンの形の小さい物。白いふち・ふわふわ浮く。触れると拾う。10秒で点滅して消える）
  - 回復（緑の電池の絵）：ライフ +1（`Health.Heal`）。ライフが満タンのときは、シールドを落とす。
  - シールド（青い盾の絵）：5秒、無敵（`Health.SetInvincible`）＋体に触れた雑魚が倒れる。体のまわりに白い輪。
- 赤い物は拾える物に使わない（赤＝危ない）。
- ボスの登場が始まったら、落ちている物とシールドは消える。回復したライフは残る（ライフはステージごとに全快なので、効くのはそのステージのボス戦だけ）。ボス戦が少し楽になるので【要相談②】。

## 5. 雑魚の種類と出方

新しい雑魚は、今の歩く雑魚のひな形を実行時に複製して作る（シーンとビルダーを変えない。絵は今の雑魚の絵を使い、色・大きさ・動きで見分ける【仮】）。

| 雑魚 | 動き | 倒し方が変わる所 | 出る場面 | 優先度 | 量 |
|---|---|---|---|---|---|
| 小さい雑魚（群れ用） | 歩く雑魚の 0.8倍・速さ 1.5倍 | 列で来る。まとめて倒す | 出来事の「群れ」・最高潮 | A | 小 |
| 強い雑魚 | 4-3 | 3回たたく。拾える物 | 最高潮 | B | 小 |

## 6. ステージの変化（進んだのが目に見える）

- **感染のもや**：ステージが始まったとき、画面全体に紫のもや（半透明の紫の板＋マゼンタの乱れの横線が数本＋四隅に濃い紫）。感染したデスクトップの画面（20章）と同じ紫とマゼンタ。

  - 晴れるたびに、乱れの線が1本ずつ、はじけて消える。背景の壁紙が、そのアプリの本来の色で見えてくる。

- **右上のゲージ**（今ある物）：80% を越えたら、ボスの影のアイコンが小さくふるえ、ゲージがゆっくり明滅する（優先度B。`PixelHud` を少し変える）。

## 7. 緊張とほっとする所・「あと少し」

- 緊張：③出来事（赤いふち・予告）、⑤最高潮（数・はさみうち・強い雑魚）。
- ほっとする：①入り（置いてある雑魚だけ）、④ひと休み（何も出ない 3秒・もやが大きく晴れる・拾える物）、連続キルの一掃（画面が一瞬きれいになる）。
- 「あと少し」を作る所
  - 最高潮に入った瞬間：もやが 25% まで晴れている。ゲージは 65%。
  - 残り3体：残っている雑魚の頭の上に、小さい白い印（探さなくてよい）。ゲージのボスの影がふるえる。
  - 最後の1体：倒した瞬間に 0.25秒のスロー（`HitStop.Request(0.25f, true)`）と白い光。残った紫がボスの位置へ吸いこまれる。
- 交互にする決まり：高い場面を2つ続けない。出来事のすぐあとに群れを出さない（必ず④をはさむ）。

## 8. 公平さ・読みやすさ・長さ

- **色**：敵と危ない物は赤いふち、プレイヤーの物と拾える物は白いふち（app-skill-visuals-design.md の 0-3 と同じ）。感染は紫。
- **予告**：危ない物は必ず 0.8秒以上の予告（影・うすい形）。出来事の最初の予告は、赤いふちと通知のあと 0.8秒。
- **同時に出す量**：落ちる物は同時に3個まで。柱・床は、必ず安全な側か足場が残る。出来事の間は、撃つ雑魚を出さない。
- **出る場所**：プレイヤーの4マス以内に雑魚を出さない（今のまま）。拾える物は床の上に落ちる（穴の上なら、手前の床）。
- **ダメージのすぐあと**：ダメージを受けてから 1秒（点滅している間）は、新しい予告を出さない。シールドの無敵の間は、ふつうに出す。
- **見返りは必ずではない**：連続キルも拾える物も、取れなくてもクリアできる。取れるとうれしいだけ。
- **長さ**
  - 雑魚の時間は、1ステージ 40〜55秒、Terminal は 30秒。ランの合計で、今より約 1分長くなるだけ【仮】。ランク（1ステージ5分を越えると減点）には響かない。
  - 場面は進み具合で切り替えるので、上手い人は短く終わる。一掃はゲージを進めるので、上手いほど速い。
  - ライフ0でやり直すとき：ボス戦で倒れたあとの雑魚の時間は、出来事を飛ばして数を半分にする案がある【要相談④】（やり直しがだれないため）。決まるまでは、今のまま同じ流れをもう1回。
- **安全のためのスイッチ**：`StagePaceTable.Enabled` を false にすると、今までの出し方に戻る（締め切りの日に問題が出たら切る）。

## 10. 作り方（実装担当へ）

### 10-1. 全体の形

- 新しい部品は `Assets/Scripts/Stage/Pacing/` に足す。シーンとビルダー（`StageLayoutsBuilder`・`RunScenesBuilder`）は変えない。シーンの作り直しもしない。
- 中心は `StagePacer`（場面を進める係）。**実行時に自分で付く**：`[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` と `SceneManager.sceneLoaded` で、`StageDirector` があるシーンなら GameObject を作って付く。`StageDirector.cs` は変えない（`Plan`・`Wave`・`Entrance` は公開されている）。
  - テスト用のシーン（`StageDirector` が無い）には付かないので、今までどおり。
- 既存のファイルで変えるのは、次の2つだけ。どちらも担当1 だけがさわる（10-3）。
  - `Assets/Scripts/Stage/ZakoSpawner.cs`：下の公開の口を足す。今の動きは、口を使わなければ変わらない。

public class StagePacer : MonoBehaviour
{
    public static StagePacer Current { get; }      // 無ければ null（ほかの部品は null なら何もしない）
    public static event Action<StagePacer> Started; // ステージごとに1回。ここで購読する
    public PacePhase Phase { get; }
    public event Action<PacePhase> PhaseChanged;    // Done ＝ ボスの登場が始まった（全部片づける）
    public float Progress { get; }                  // 0〜1（1画面＝倒した数、ほか＝進んだ x）
    public int StageNumber { get; }                 // 1〜（RunState.CurrentIndex + 1）
    public bool IsFinal { get; }                    // Terminal

    public AppTheme Theme { get; }
    public Sprite Icon { get; }
    public Rect PlayArea { get; }                   // 今の画面（1画面は部屋、ほかはカメラ）
    public Transform Player { get; }
    public ZakoSpawner Spawner { get; }
    public int Remaining { get; }                   // ボスまでの残りの数（ノルマの無いステージは -1）

// Assets/Scripts/Stage/ZakoSpawner.cs に足す（担当1）
public bool Paused { get; set; }                         // true の間、自分からは出さない

public IReadOnlyList<Health> AliveList { get; }
public GameObject Template(int index);                   // 0＝歩く、1＝撃つ（複製して新しい雑魚を作る元）

// Assets/Scripts/Stage/Pacing/Events/StageEvent.cs（担当2）
public abstract class StageEvent   // 雨・柱床・群れが継ぐ
{
    public virtual bool SpawnsOwnZako => false; // true（群れ）：③の雑魚は出来事が SpawnNow で出す。false：StagePacer が出す
    // strength：1＝弱い、2＝ふつう、3＝強い。zakoBudget：出来事が出してよい雑魚の数（SpawnsOwnZako が false なら 0）
    public abstract void Begin(StagePacer pacer, AttackRunner hazardRunner, int strength, int zakoBudget);
    public abstract bool Tick(float dt);   // false を返したら終わり
    public abstract void End();            // 出した物を全部消す（途中で呼ばれてもよい）
}
public static class StageEventTable
{
    public static StageEvent For(SkinId skin, int stageNumber, bool isFinal);
    public static int ExtraZako(SkinId skin, int stageNumber, bool isFinal); // 全部の数への上乗せ（2-3）。StagePacer が Start で AddQuota に足す
    public static string ToastOf(SkinId skin);
}
