## 2. 全体の流れ（通し）

```
RunTitle（読み込み方を選ぶ）→ ステージ1 → ステージ2 → … → RunResult →（Enter／ボタン）→ RunTitle
```

- **シーンの切り替え**：画面を0.4秒で暗くしてから切り替え、0.4秒で明るくする。文字は出さない。
- **ステージ**
  - 1画面（Stage_Desktop）：雑魚を全員倒すとボスが出る。
  - 横スクロール・ウィンドウ移動：道中を進んでボス部屋に入ると、入口が閉じてボスが出る（道中の雑魚は倒さなくてよい）。
  - ボスにとどめを刺す（正常化する）とクリア。
  - 正常化してから2.5秒後に、次のステージかリザルトへ進む。
- **ライフ0**：1.5秒後に、同じステージを最初からやり直す。やり直すと次のものが戻る。
  - ライフ：全快
  - 能力：そのステージを始めたときの状態
  - クールタイム：リセット
  - 雑魚：全員復活
  - ボス：ゲージ0、第1形態
- **リザルト**：正常化したアプリ・使用時間・手に入れた能力の一覧と、リトライ回数を出す。
- **開発用**：Stage_Desktop を直接再生すると、サンプルデータでランを作って始まる。

ゲームの進行は `GameSession` が持つ（シーンをまたいで残る）。各ステージの進行は `StageDirector` が担当する。

## 3. 使用データとステージの決め方（通し）

### 読み込み方（タイトルで選ぶ）

| ボタン | 中身 |
|---|---|
| 自動 | `~/Library/Application Support/DefaultCompany/Team1/usage.json` を読む |
| サンプル | ゲームに同梱のデータ。Chrome 8時間、VS Code 25時間、Finder 10時間（Finder は対応表に無いので出ない） |
| 手入力 | 対応アプリごとに、スライダーで0〜40時間を入れる。0時間のアプリは出ない |

- 対応アプリが1つも無いときは、タイトルに理由を出す。プレイヤーはサンプルか手入力を選び直す。
- usage.json の形式
  - 一番外側は配列。
  - 1つのアプリは `{ "id": バンドルID, "displayName": 表示名, "usageSeconds": 過去7日間の合計秒数, "iconPath": アイコンのパス }`。
  - `usageSeconds` が null なら0として扱う。

### ステージの並べ方

1. 対応表（`AppCatalog`）に無いアプリは捨てる。照合はバンドルIDの前方一致で、大文字と小文字は区別しない。
2. 同じ対応アプリに当たるデータが複数あれば、使用時間を足す。
3. 1アプリ＝1ステージ。使用時間が短い順に並べる。一番使ったアプリが最後のボスになる。

- **今の対応アプリは2つだけ**：Chrome（`com.google.Chrome`）と VS Code（`com.microsoft.VSCode`）。

### 強さ

- 強さ t ＝ 使用時間 ÷ 20時間（0〜1 に収める）。20時間は【仮】。
- t に応じて、下の値を最小から最大の間で決める。
- 元のアセットは書き換えず、ランの間だけ使う複製を作る。テストシーンは元のアセットの値（設計メモの基本値）のまま。

| 対象 | 値（t＝0 → t＝1） | 基本値（テストシーン） |
|---|---|---|
| ボスのゲージの最大値 | 80 → 140 | 100 |
| 第2形態の待ち時間 | 0.8秒 → 0.6秒 | 0.8秒 |
| 能力「新しいタブ」の距離 | 5マス → 8マス | 6マス |
| 能力「ブレークポイント」のゲージ増加 | +10 → +16 | +12 |

例：サンプルデータの場合

| ステージ | アプリ | 使用時間 | 強さ t | ゲージ最大値 | 第2形態の待ち時間 | 能力の値 |
|---|---|---|---|---|---|---|
| 1 | Chrome | 8時間 | 0.4 | 104 | 0.72秒 | 新しいタブ 6.2マス |
| 2 | VS Code | 25時間 | 1.0 | 140 | 0.6秒 | ブレークポイント +16 |

### 操作

|---|---|---|
| 移動 | WASD／矢印キー | 左スティック／十字キー |
| ジャンプ | Space | A（下のボタン） |

| ダッシュ | K／左 Shift | RT |
| 能力を使う | 1／2／3 | Y／B／RB |
| 選んでいる枠を切り替える | Q（前）／E（次） | LB（次） |
| 選んでいる枠の能力を捨てる | X を0.5秒長押し | LT を長押し |

### 移動

| 項目 | 値 |
|---|---|
| 体の大きさ | 0.7×1.0マス（被弾範囲も同じ形） |
| 移動速度 | 毎秒7マス |
| ジャンプ | 高さ3.2マス、頂点まで0.38秒。ボタンを早く離すと低く跳ぶ |
| 崖から落ちたあとの猶予（コヨーテタイム） | 0.1秒 |
| 着地前のジャンプ入力の受け付け | 0.12秒 |

### ダッシュ（仕様書 3.2）

- 向いている方向（入力があればその方向）へ、毎秒16マスで0.15秒進む。距離は2.4マス。
- ダッシュ中は重力がない。無敵はない。
- 空中では、着地するまでに1回だけできる。
- 次のダッシュまでの間隔は0.4秒。
- ジャンプ・壁に当たる・被弾のどれかで終わる。

### 近接（仕様書 3.3、本番の近接は未定）

- 前方 0.8×0.6マスに、0.12秒だけ判定を出す。次に振れるまでの間隔は0.3秒。空中でも振れる。
- 雑魚には1ダメージ。雑魚の HP は5なので、5回で倒せる。
- ボスにはゲージが +4。
- 判定が出ている間は、向きが変わらない。移動の入力は効くので、後ずさりになる。

### ライフ

- 3つ。どの攻撃でも、1回当たると1つ減る。
- 当たったあと1.0秒は無敵で、点滅する。
- 当たると吹き飛ばされ、少しの間操作できない。ボスの攻撃なら、吹き飛ばしは (6,5)、操作できない時間は0.25秒。
- 雑魚とボスの体に触れてもダメージを受ける。
- 0になると操作できなくなり、やり直しになる（2章）。

### アニメーション

- Animator に `SpeedX`・`VelocityY`・`IsGrounded` のパラメータを作れば、自動で値が入る（`PlayerAnimationBridge`）。
- 近接・ダッシュ・ジャンプ・着地はイベントで知らせている。アニメーションはまだつないでいない。

## 6. 能力（通し）

### 持ち方と操作

- 3枠まで持てる。新しい能力は、一番前の空き枠に入る。
- 3枠とも埋まっているときに新しい能力を手に入れると、入れ替え待ちになる。
  - 1／2／3：入れ替える枠を選ぶ。
  - X 長押し：拾わない。
  - 入れ替え待ちの間も、ゲームは止まらない。
- 捨てた枠は空きのまま残る。ほかの枠は詰めないので、キーと能力の対応は変わらない。
- 同じ能力は2つ持てない。
- のけぞり中と入れ替え待ちの間は、能力を使えない。

### ランの中での扱い

- 能力は、ボスを正常化したときにだけ手に入る（拾うアイテムは PlayerTest だけ）。
- 能力は次のステージに持ち越す。
- やり直したときは、そのステージを始めたときの能力に戻る。

### クールタイム

- 能力ごとに数える。捨てて拾い直しても、別の枠に入れ直しても、残り時間はそのまま。
- ステージが変わるときと、やり直すときは、リセットされる（シーンを読み込み直すため）。

### 能力の中身

| 能力 | 手に入るボス | 効果 | クールタイム |
|---|---|---|---|
| 新しいタブ | Chrome | 前方へ6マス（ランでは5〜8マス）瞬間移動する。壁は通り抜けず、その手前で止まる。空中でも使える。無敵はない | 3秒 |
| ブレークポイント | VS Code | 4マス先の床に赤丸を出し、0.3秒後に縦の柱（幅1.5×高さ6）で0.2秒判定する。ゲージは +12（ランでは +10〜16）、雑魚には3ダメージ | 3秒 |

## 7. ボスの共通ルール（通し）

- **ウイルス解除ゲージ**
  - HP の代わりに、ゲージを持つ。基本の最大値は100（ランでは80〜140）。
  - 攻撃の「ゲージ増加」の分だけ増える。ダメージの量は見ない。
- **行動**
  - 戦闘が始まってから1秒後に、最初の攻撃をする。
  - 第1形態は2つの技を交互に出す。第2形態は、同じ技が続かないようにランダムに選ぶ。
  - 攻撃のあとの待ち時間：第1形態は1.2秒、第2形態は0.8秒（ランでは0.8〜0.6秒）。
  - 2回攻撃するごとに移動する。
- **形態変化**（ゲージ50%）
  - 攻撃をやめ、画面に出ているボスの弾だけを消す。落下物・赤い波線・足場として残ったポップアップは残る。
  - 1.5秒の間、無敵で点滅する。この間も体当たりの判定はある。
  - 1.5秒たったら第2形態になる。
- **ゲージ100%：ウイルス本体の追い出し**（State＝Ejected）
  - 攻撃をやめ、出ている攻撃をすべて消す。体当たりの判定もなくなる。
  - ウイルスが押し出され（大きい煙）、きれいになったウィンドウがきらめいて上へ消える。
  - 小さくなったウイルス本体が、プレイヤーと反対の向きへ逃げる。ボスの子に置いた「追い出されるウイルス」で、歩く雑魚と同じ動き、毎秒4.5マス。攻撃してこない。触れてもダメージを受けない。時間切れはない。
  - ゲージは白になる。
- **正常化**（ウイルス本体にとどめを刺したとき）
  - 1回当てると大きい煙ではじけて消える。そこで能力をプレイヤーに渡す。空き枠があればそこに入り、満杯なら入れ替え待ちになる。
  - 2.5秒後に次のステージかリザルトへ進む（今までと同じ）。
- **プレイヤーへのダメージ**：ボスの攻撃も体当たりも、ライフが1減る。

## 10. 画面表示（すべて仮）

## 14. グラフィック（feature/graphics、まだコミットしていない）

デザイン担当の絵（プレイヤーの歩き5コマ、ウイルスの煙5コマ、壁紙、ウィンドウの見本）に合わせて、ゲームの絵をすべて差し替えた。

- **絵の置き場**
  - `Assets/Sprites/Provided`：デザイン担当の絵（そのまま）。
  - `Assets/Sprites/Generated`：見本の色と雰囲気に合わせた仮の絵（`Tools/art/gen_sprites.py` が作る）。同じ名前・同じ大きさで置き換えれば差し替わる。
  - 背景（`Generated/Background/Bg_Desktop.png`）は、デザイン担当の壁紙（`Provided/Bg_Wallpaper.png`）から、下の道路だけを消して丘を伸ばしたもの。床はゲームの床の絵（道路）が描く。
- **ドットの大きさ**
  - ゲーム中の物：1マス＝18ドット。プレイヤーの絵の頭から足まで（18ドット）が、当たり判定 0.7×1.0 マスにちょうど合う。デザイン担当の絵は3倍で描かれているので、取り込みは 54。
  - 背景：1マス＝15ドット（320×180 の絵が画面にちょうど収まる）。ゲーム中の物とはドットの大きさが少し違う。
- **当たり判定は変えていない**：判定は今までどおり四角に付けたまま、絵は別の子に置いた。全シーンとボスのプレハブで、判定の位置・大きさが差し替えの前と同じことを確かめた。
- **作り方**：メニュー「Tools/Team1/グラフィックを適用」（取り込み設定・攻撃データ・能力・ボスへの割り当て・プレイヤーの Animator）→ 各シーンの作成ツール。シーンの作成ツールは、最初に「グラフィックを適用」を自動で呼ぶ。ボスのプレハブは毎回作り直す（パスは同じなので、対応アプリ表からの参照は切れない）。
- **実行中の演出**（判定には関わらない）
  - ボスのウイルスの煙と顔（`BossVirusOverlay`）：ゲージに合わせてはがれる。形態変化で赤、正常化で大きい煙。登場したときにも煙。
  - 雑魚・プレイヤーが倒れたときの煙（`DeathVfx`）。近接の斬撃と当たったときの火花、ダッシュの残像、新しいタブのウィンドウ（`PlayerVfx`）。
  - 攻撃の予告：点線の枠、ブレークポイントの赤丸、落下物の影、VS Code が現れる場所の文字カーソル。柱・赤い波線は絵を並べて伸ばす（ドットが伸びない）。
- **アプリの色（トンマナ）**（2026-11-17 まさぴ〜決定）
  - アプリのアイコンの色を、そのアプリのステージと能力の色にする。ステージの色と能力の枠の色で、どのアプリか分かる（文字を出さない）。
  - **ステージ**：壁紙・床・壁・足場（フォルダ）・ボスのゲージの色を塗り替える（`StageTheme`。絵は同じで、色だけ入れ替える）。
    - Chrome：昼の青い空と緑の丘に、赤と黄の差し色。足場は黄色、床の縁は赤、ゲージは4色。
    - VS Code：夜の暗い空に青の丘。足場・床の縁・ゲージは青。
  - **能力**：手に入れたアプリの色。
    - 枠の縁：新しいタブは Chrome の4色（上が赤、右が黄、下が緑、左が青）、ブレークポイントは青。
    - 効果：新しいタブのウィンドウのタイトルバーが Chrome の4色、ブレークポイントの柱が青。
  - **変えないもの**：
    - 敵の攻撃は赤系のまま（自分の能力と見分けるため）。
    - ウイルス（雑魚・ボスの煙と顔）は、どのステージでも黒と赤。
  - **色の置き場**：`Assets/ScriptableObjects/Themes/Theme_Chrome`・`Theme_VSCode`。対応アプリ表の各アプリと、各能力が指している。色を直すときは、このアセットを直す（作成ツールは上書きしない）。
  - **塗り替わる場所**：ランのステージ（Stage_Desktop）だけ。テストシーン（BossTest・StageTest・PlayerTest）は元の色のまま。能力の枠と効果の色は、どのシーンでも付く。

## 15. ステージの種類（2026-11-17 まさぴ〜決定。配置・数値は【仮】）

- **割り当て**：アプリごと。対応アプリ表の「ステージのシーン」の欄で決める（`RunScenesBuilder` が入れる）。
  - Chrome：横スクロール（`Stage_Scroll`）
  - VS Code：ウィンドウ移動（`Stage_Windows`）
  - それ以外のアプリ：1画面（`Stage_Desktop`、4章）
  - サンプルデータでは、横スクロール → ウィンドウ移動 → リザルトの順になる。
- **共通**
  - 最後に、いつものボス部屋（横20×高さ11.5マス、フォルダ2枚）がある。ボスの技は部屋の広さを前提にしているので、形は変えていない。
  - ボス部屋に入ると入口の壁が閉じ、カメラが止まり、ボスが出てくる（`BossRoomGate`）。道中の雑魚は倒さなくてよい。
  - ボスの出る位置は、ボス部屋の床の真ん中からのずれ（対応アプリ表の「ボスが出てくる位置」）。
  - やり直し（ライフ0）は、今までどおりステージの最初から。ボス部屋の前から始める「中間地点」は入れていない。
  - ステージの色は、そのアプリの色（14章のトンマナ）。
- **横スクロール**（`Stage_Scroll`、全体の長さ 95マス）
  - 壁紙の上を右へ進む。カメラはプレイヤーを横に追いかける（`StageCamera`）。
  - 穴が3つ。落ちるとライフが1減り、直前に立っていた床の上に戻る（`PitRecovery`）。無敵の間に落ちたときは、戻るだけ。
  - 開いたり閉じたりするウィンドウの足場が3枚（穴の上の橋と、上の道）。
  - 降ってくる通知：x 28〜62 の間、2.2秒ごとにプレイヤーの近くの画面の上に出て、0.8秒後に落ちる（落ちる床に影）。当たると1ダメージ。
  - 雑魚：歩く×4、撃つ×2。
- **ウィンドウ移動**（`Stage_Windows`、部屋3つ＋ボス部屋）
  - エディタのウィンドウ（1画面ずつ）を渡り歩く。部屋の中はエディタの暗い色で、上にタイトルバー（アプリの色）と閉じるボタン。
  - カメラは、プレイヤーがいる部屋へスッと動く。
  - 部屋1：開いたり閉じたりするウィンドウの足場を、順番に渡る。
  - 部屋2：まん中にファイアウォール。右の壁の出入り口は高い所にあるので、足場を登る。
  - 部屋3：ファイアウォール2つ（ずらして交互）と、消える足場。
  - 雑魚：歩く×3、撃つ×3。
- **ギミック**（すべて【仮】の値）
  - 開いたり閉じたりするウィンドウ（`BlinkingPlatform`）：2.2秒出て、1.4秒消える。消える前の0.6秒は点滅し、消えている間はうすく形だけ出る。
  - 降ってくる通知（`NotificationDropper`）：ボスの落下物と同じ部品（`FallingObject`）を使う。
  - ファイアウォール（`Firewall`）：1.6秒オン、1.8秒オフ。オンになる前の0.6秒は、うすく点滅して知らせる。オンのときに触れると1ダメージ（吹き飛ばされる）。
- **作り方**：「Tools/Team1/ランのシーンを作成」が、3つのステージをまとめて作る（`StageLayoutsBuilder`）。
- **確かめたこと**：Unity で、タイトルから横スクロール・ウィンドウ移動・リザルトまで自動で通した（エラー0件）。
  - 穴に落ちるとライフが1減って戻る。
  - 消える足場は、出たり消えたりする。
  - 通知は降ってくる（6秒で3個）。
  - ボス部屋に入ると入口が閉じて、カメラが止まる。
  - ボスはボス部屋の決まった位置に出る。
  - 炎が出ているファイアウォールに触れると、ライフが1減る。
  - 手で遊んだときの難しさ・長さは、まだ確かめていない。
