# スキルの見た目のデザイン（見ただけで「あのアプリ」と分かるようにする）

- 書いた日：2026-11-18（夜）
- 書いた人：Claude（Fable 5.2。企画・アートディレクション）。まさぴ〜の依頼。
- 実装：Opus 5.5 の実装担当が 3〜4人で並行して行う（14章）。
- 締め切り：開発 2026-11-20。
- 対象：ボスの技・プレイヤーの能力・当たったときのエフェクトの**見た目だけ**。
  - 当たり判定・秒数・ダメージ・ゲージは変えない。変えたい所は【要相談】（15章）。
  - 動きと秒数の元：Chrome・VS Code とカテゴリの能力は [設計メモ](app-boss-and-ability-design.md) 4〜5章と [今の実装](implementation-status.md) 6・17・22章。Finder・Premiere Pro・Terminal は [技の仕様](app-boss-skills-design.md)。**食い違ったら、そちらが正しい。**
- 細部（色の16進・ドットの数・秒数の目安・文字列）は、すべて【仮】。
- この仕様は、コードと今までの画面の画像を読んで書いた。Unity では動かしていない。
- 見本：チームの別の試作の動画（Office＝棒グラフ・円グラフ・折れ線、Unity＝立方体・球・警告の枠、Steam＝照準・コントローラー・実績解除の通知）。「アプリの UI や中身の形が、そのまま攻撃になる」を、全部のスキルに広げる。

## 0. 全体の方針

### 0-1. 「見ただけでアプリが分かる」ための決まり

1つの技に、次の3つのうち**2つ以上**を入れる。

| | 中身 | 例 |
|---|---|---|
| 形 | そのアプリの UI の部品の形にする。丸・四角・光の玉のままにしない | タブの台形、エラーの赤丸に×、通知バッジ、棒グラフ、吹き出し |
| 動き | その UI の動き方をまねる | ポップアップは「パッ」と出る。通知は横からすべり込む。文字は1字ずつ打たれる。グラフは下から伸びる |
| 色 | そのアプリの色（アイコンの色から作った `AppTheme`）と、UI の決まった色 | Office のグラフの青・オレンジ・黄、エディタの暗い地に色つきの文字 |

- ロゴは描き写さない。形・色・UI の部品で「らしさ」を出す。
  - アプリのアイコンのドット絵（`PixelIcon`。ゲームが Mac から読んだ物）は、今までどおり使ってよい（汎用スキン・通知）。
- 技の名前や効果の説明の文章は出さない（今までの決まり）。
- アプリの UI をまねた**短い文字は、飾りとして使ってよい**（"404"、"Error"、"#REF!"、"New"、通知の題名など）。
  - 決まった文字列だけを使う（各章に書いた物）。本物のファイル名・URL・Mac のアカウント名・使用時間は出さない（Spotlight の `PLAYER` と同じ理由。発表で映る）。
  - 数値の説明は出さない（見本の動画の「攻撃+30%」のような行は作らない）。
  - 英字は Press Start 2P（英数字と記号だけ）、日本語は DotGothic16。字の高さは 0.4マス以上（7〜8ドット）。それより小さい字は、ドット絵で描く。
  - 記号（⏸ ▶ ■ ✓ ✦ ⏎ ⌘ ♪ など）は、どちらのフォントにも無い。**記号は全部ドット絵で描く**（この文書では、形を伝えるために記号で書いている）。
  - 文字が読めなくても、形と色だけで避けられる・当てられること。

### 0-2. ハッタリの出し方

現実の UI に忠実である必要はない。次の5つで大げさにする。

1. **出るとき**：大きさを 0 → 115% → 100%（0.1秒）。UI が「パッ」と出る感じ。
2. **数を見せる**：予告で「これから何発来るか」を UI の数字や並びで見せる（エラーの数のバッジ、並ぶタブ）。
3. **当たった瞬間**：ヒットストップ・画面のゆれ・白い光・アプリの「当たった絵」（1章）。
4. **消えるとき**：ただ消さない。閉じる・砕ける・ゴミ箱に入る・ログアウトする。
5. **大きい物は画面の端まで**：線・帯・柱の飾りは、判定より外へ伸ばしてよい（0-3 の決まりの中で）。

### 0-3. 読みやすさの決まり

- **敵とプレイヤーの見分け方**【要相談 1】
  - 敵の攻撃：中はアプリの形と色。**ふちは赤 `#FF453A`（1ドット）**。予告は必ず赤。
  - プレイヤーの攻撃：中はアプリの形と色。**ふちは白 `#FFFFFF`（1ドット）**。赤は使わない（ブレークポイントの赤丸だけ例外。3-6）。
  - 今の決まり（「今の実装」14章【確定】「敵の攻撃は赤系のまま」）を、「赤いふちと赤い予告」に言い直している。Finder・Premiere Pro・Terminal の技は、すでに青・黄・緑を使っている。
- **判定と絵**
  - **明るい芯＝当たり判定**。芯は判定の四角・円の中に描く。
  - 飾り（尾・ふち・きらめき）は、判定の外へ 3ドットまではみ出してよい。尾は後ろへ何ドットでもよい（暗く・うすくする）。
  - 判定の無い飾り（数字・文字・かけら）は、明るさを芯の 7割以下にするか、5割すかす。
  - 敵の攻撃で、判定より大きく見える絵は作らない。プレイヤーの攻撃は、判定より大きく見えてよい。
- **予告**：今の予告（赤丸・影・点線の枠・1.0秒などの秒数）は、形を UI に変えても、**同じ場所・同じ大きさ・同じ秒数**で出す。最後の 0.3秒は点滅（今と同じ）。
- **ウイルス**（雑魚・ボスの煙と顔・逃げるウイルス本体）は、今までどおり黒と赤。スキンをかけない。
- **重ならない順番**：1-6 の表。当たった絵と通知は、弾と予告をかくさない位置・うすさにする。

### 0-4. 大きさの目安（1マス＝18ドット）

| 物 | 大きさ（マス） | ドット |
|---|---|---|
| 画面（カメラの縦 12マス） | 21.3×12 | 384×216 |
| プレイヤー | 0.7×1.0 | 13×18 |
| 雑魚 | 約 0.7×0.7 | 約 13×13 |
| ボス（判定） | 4×3 | 72×54 |
| ボスの着ているウィンドウの中のアイコン | — | 24 |
| アプリのアイコン（`PixelIcon`） | — | 12・16・24 |

- 絵は、コードの中のドット絵（`RuntimeSprites.FromAscii`）で描く。絵のファイルは足さない。
  - 1枚は 32×32 ドットまでを目安にする（手で書ける大きさ）。
  - それより大きい物（柱・ウィンドウ・帯・円）は、小さい絵を並べるか、四角と線で組む（`FinderArt.Ring`・`MakeStrip` の作り方）。
  - 伸ばすと形がくずれる絵（柱・波線）は、上・中・下の3枚に分けて並べる。
- 1つの絵に使う色は 4〜6色。黒いふちは付けない（赤か白のふちを使う）。

## 1. 共通の仕組み

### 1-1. スキン（アプリの見た目の組）

- 攻撃の見た目を、**スキン**と**枠**の2つで決める。「どのアプリか」がスキン、「どの種類の攻撃か」が枠。
- 理由：代用ボス（Slack・Figma など）は Chrome か VS Code の技を使い、その場で作る能力は7つのひな形から選ぶ。アプリごとに技を描くのではなく、「スキン × 枠」で絵を決めれば、全部のアプリに広がる。
- 今は、代用ボスの技の絵は Chrome・VS Code のまま（オレンジの広告・赤い柱）。塗り替えもしていない。

**スキンの一覧**

| スキン | 当たるアプリ | 章 |
|---|---|---|
| Browser | Chrome・Safari・Arc・Firefox・Edge・Brave | 2 |
| Dev | VS Code・Cursor・Xcode・Unity・Unity Hub・IntelliJ・GitHub Desktop・シミュレーター | 3 |
| Office | Word・Excel・PowerPoint・Keynote・Pages・Numbers・Notion・メール・カレンダー・メモ | 4 |
| Creative | Figma・Photoshop・Illustrator・After Effects・Blender・OBS・GarageBand | 5 |
| Game | Steam・Minecraft Launcher・Epic Games Launcher | 6 |
| Chat | Slack・Discord・LINE・メッセージ・Teams・Zoom（ボスのとき） | 7 |
| AI | ChatGPT・Claude・Codex・Perplexity | 8 |
| Media | ミュージック・Spotify・QuickTime・TV・Podcast・VLC・IINA | 9 |
| Generic | 上のどれでもないアプリ | 10 |
| Finder / Premiere / Terminal / Zoom | 専用の技・能力を持つ物 | 11〜13・7-3 |

- **決め方**【仮】：アプリの名前とバンドルID → スキン、の表を新しく1つ作る（名前は設計メモ9章の表）。
  - 今のカテゴリの表（`AbilityCatalog`）は使えない。能力のあるカテゴリ（ブラウザ・開発・Office・クリエイティブ・ゲーム）しか入っていない。その場で作る能力と、表に無い代用ボスは `Unknown` になる。
  - 順番：専用（Finder・Premiere Pro・Terminal・Zoom の能力）→ 名前の表 → カテゴリ → Generic。
- **スキンが決まらない・まだ作っていないとき**：Generic。Generic も無ければ、今の見た目のまま。**どの段階でも遊べる状態を保つ。**
- スキンを持つ所：
  - ボス：ステージを作るとき（`StageDirector`）に、そのステージのアプリから決めて、ボスの攻撃を出す部品（`AttackRunner`）に渡す。テスト用のシーンでは、Chrome＝Browser、VS Code＝Dev。
  - プレイヤー：能力ごと。カテゴリの能力はカテゴリから。アプリ専用の能力はそのアプリ。その場で作る能力は、作るとき（`AbilityForge`）にアプリの名前から決めて、能力に持たせる。
  - 近接：スキン無し（1-4 の「近接」）。

**枠の一覧**（当たり判定の大きさは今のまま。絵の大きさは目安）

| 枠 | 使う攻撃（攻撃データの名前で決める） | 判定（マス） | 絵（ドット） |
|---|---|---|---|
| 小弾 | タブ手裏剣、拡散ショット | 0.6×0.4／0.45 | 14×12 まで |
| 長弾 | エラー弾 | 1.0×0.3 | 22×9 まで |
| 投げ物 | ボム、ロブ弾、トラップ弾 | 0.5／0.45 | 12×12 |
| 柱 | ブレークポイント（ボス・能力）、ピラー、棒グラフ、連続ピラー | 幅1.5（能力は1.2〜1.9） | 幅27。上・中・下を並べる |
| 床 | 赤い波線、トラップ弾の床 | 2×0.4／2.6×1 | 36×7／47×18 |
| 塗り | バケツ塗り、ペイント | 3.5×3.2 | 63×58。四角と線で組む |
| 円 | ボムの爆発、ノヴァ | 直径 4〜5.4 | 輪とかけらで組む |
| 窓 | ポップアップ出現（足場になる） | 3×2 | 54×36 |
| 落下物 | エラーウィンドウ落下 | 3×2 | 54×36 |
| 上の列 | タブ増殖 | 1.5×0.6 | 27×11 |
| ワープ | VS Code の瞬間移動、新しいタブ | — | — |

- 枠は、攻撃データの名前から決める（`Attack_Chrome_TabShuriken…` → 小弾、など）。**攻撃データのアセットと作成ツールは書き換えない**（ぶつかるのを防ぐ。14章）。
- 専用の技（`Custom`。Finder・Premiere Pro・Terminal）と、ロックオン（Zoom）は、枠を使わない。自分の部品の中で絵を持つ（今のまま）。

**スキンの絵の作り方（実装担当への形）**【仮】

- 1スキン＝1ファイル（`BrowserSkin.cs` など）。次の2つを返す。
  - `Dress(枠, 場面, 情報)`：攻撃の物に絵を付ける。
    - 情報：付ける先・判定の大きさ・敵かプレイヤーか・アプリの色（`AppTheme`）・アプリのアイコン・何個目か（連射・並びの番号）。
    - 場面：**予告**（出た）→ **本体**（判定が始まった）→ **着地**（床・壁に当たった。弾・落下物）→ **消える**（時間切れ・当たって消えた）。弾・指定位置の判定・落下物の部品が、この4つを知らせる。
  - `Hit(強さ, 情報)`：当たった絵を出す（1-2）。
- 絵を付けたら、今の絵（攻撃データの絵）はかくす。スキンが「この枠は無い」と返したら、今の絵のまま。
- プレイヤー版は、敵版と同じ形で、「赤いふち → 白いふち」「赤い部分 → アプリの色」にする。各章の表は敵版で書く。違う所だけ書き足す。
- **絵を決める順番**（上から先に当たった物）
  1. その能力・技だけの見た目がある：カテゴリの能力（新しいタブ 2-4、ブレークポイント 3-6、棒グラフ 4-1、バケツ塗り 5-1、ボム 6-1）、アプリ専用の能力（7-3・11-3・12-1）、専用の技（11〜13章）。
  2. スキンの、その枠の絵（各章の表と 1-7）。**その場で作る能力は、ここで決まる**（Slack の「連続ピラー」は、棒グラフではなく、Chat の柱＝メンションの連打が3本）。
  3. Generic の、その枠の絵（10章）。Finder・Premiere Pro・Terminal のボスが持つ、Chrome・VS Code の技の残り（瞬間移動など）も、ここ。
  4. 今の絵のまま。

### 1-2. 当たったときのエフェクト（1つの部品）

**何を入れたら、何が出るか。**

- 入れる物：
  1. 当たった位置
  2. 当たった相手（ボス・雑魚・逃げるウイルス本体・プレイヤー）
  3. 攻撃のスキン
  4. 強さ（下の表）
  5. 向き（攻撃から相手へ。かけらの飛ぶ向き）
- 出る物：当たった絵・かけら・相手の光り方・ヒットストップ・画面のゆれ・（あれば）隅の通知。

**強さの決め方**【仮】

| 強さ | いつ |
|---|---|
| 小 | 残り続ける床・塗りの2回目からの当たり。ロックオンの、同じ相手への2本目から。同じ相手に 0.15秒以内に続けて当たったとき |
| 軽い | 近接。ゲージ増加 7 以下、または雑魚へのダメージ 2 以下の能力 |
| 重い | ゲージ増加 8 以上、または雑魚へのダメージ 3 以上（ブレークポイント・ボムの爆発・ノヴァ・zip の散弾など） |
| とどめ | ボスのゲージが 100% になった一撃。逃げるウイルス本体を倒した一撃 |
| 被弾 | 敵の攻撃・体当たりが、プレイヤーに当たった |
| ダウン | プレイヤーのライフが 0 になった |

**出る物の表**【仮】

| 強さ | 当たった絵 | かけら | 相手 | 止める | ゆれ（マス・秒） | ほか |
|---|---|---|---|---|---|---|
| 小 | スキンのかけら 1個（6〜8ドット） | — | — | — | — | — |
| 軽い | スキンの当たった絵・小（12〜16ドット、0.2秒） | 3個 | 白く 0.05秒 | — | — | — |
| 重い | スキンの当たった絵・大（20〜24ドット、0.3秒）＋白い輪が広がる（直径 0 → 2.5マス、0.15秒） | 6個 | 白く 0.08秒 | 0.05秒 | 0.06・0.12 | — |
| とどめ | 大を 1.5倍。白い輪を2重 | 12個 | 白く 0.12秒 | 0.12秒 | 0.15・0.3 | 画面全体を白く（4割、0.06秒）。隅の通知（1-5） |
| 被弾 | スキンの「エラーの絵」（16〜24ドット、0.4秒。プレイヤーの頭の上 0.6マス） | 赤いかけら 4個 | 赤 → 白 → 元（0.12秒） | 0.08秒 | 0.1・0.2 | 画面のふちを赤く（幅 0.5マス、3割、0.15秒） |
| ダウン | 被弾の絵を 2倍にして、画面のまん中寄りへ | 8個 | — | —（ゲームオーバーの処理とぶつかるので止めない） | 0.15・0.3 | 今の倒れた煙（`DeathVfx`）はそのまま |

- 当たった絵は、相手の体の上ではなく、**当たった位置から外へ 0.3マスずらして**出す（ボスの顔・弾をかくさない）。上へ 0.4マス浮きながら消える。
- かけらは、向きの先へ扇状（±40°）に飛ぶ。速さ 6〜10マス/秒、重力あり、0.3〜0.5秒で消える。
- 雑魚は1回で倒れる。倒れたときは「当たった絵」＋今の煙。強さは攻撃のとおり（近接なら軽い）。
- ボスが形態変化の演出中（無敵）のときは、今は「当たった」の知らせが出ない。何も出さないままでよい（足すなら優先度 C）。
- 新しいタブ（瞬間移動）は当たらないので、何も出ない。

**どこで知るか**（今ある知らせを使う）

- 攻撃の判定が当たった：`Hitbox.Hit`。ゲージが増えた：`VirusGauge.Gained`。ダメージを受けた：`Health.Damaged`。満タン：`VirusGauge.Filled`。
- 今の当たった情報（`DamageInfo`）には、位置・攻撃した本人・陣営しか無い。**スキンと、エラーの絵の種類（短い名前。空でよい）の2つを足す**（攻撃の判定を作るときに入れる）。これが共通担当の最初の仕事。
  - ダメージは、ほぼ全部が攻撃の判定（`Hitbox`）を通る。通らないのは、zip圧縮の吸い込み（`FinderZipHolder`）と、穴に落ちたとき（`PitRecovery`）の2つ。
  - 専用の技（`Combat/Custom/`）は、自分で作った判定に、スキンと種類を入れる。入れるのは、その技の持ち主（14-1）。Terminal の技ごとの字（13-1）は、この種類で選ぶ。
  - **スキンが入っていない当たり**：プレイヤーが受けたなら、そのステージのボスのスキン。敵が受けたなら Generic。穴に落ちたときは、エラーの絵を出さない（今のまま）。

### 1-3. ヒットストップ・画面のゆれ・光り方

- **ヒットストップ**【要相談 2】：入口は1つにする。
  - ゲームの時間の速さを一瞬だけ小さくして、実時間で戻す（Terminal の再起動が今やっている方法と同じ。そちらもこの入口を使うように直す）。
  - 時間の速さが 1 でないとき（暗転・デスクトップの画面・再起動の演出）は、何もしない。
  - 戻すのは、時間の速さが「自分が入れた値のまま」のときだけ（止めている間に、ゲームオーバーなどが 0 にしたら、さわらない。再起動の今の作りと同じ）。
  - 止まっている間に次の頼みが来たら、長い方に合わせる（足さない）。
  - 1秒の間に止める合計は 0.2秒まで。それより多い分は捨てる（連続で当たる能力で、ゲームが重く見えないように）。
  - 強さ「小」は止めない。
- **画面のゆれ**：`StageCamera.Shake(大きさ, 秒)` だけを呼ぶ（1画面のステージでも動く）。
  - 似た入口 `TerminalCameraShake.Shake(秒, 大きさ)` は、引数の順番が逆。新しいコードからは呼ばない。
  - 強いゆれの間は、弱いゆれで上書きしない（今の作りのまま）。
- **光り方**：相手の絵を、白 1色にして重ねる（0.05〜0.12秒）。プレイヤーは今の点滅（無敵時間）の前に、赤 → 白を 0.12秒。
  - ボスは、着ているウィンドウだけ白くする（煙と顔は白くしない）。
  - ボスのウィンドウの**乱れ**（重い・とどめ）：ウィンドウの絵を横に 3つに切って、まん中だけ 2ドット横へずらす（0.06秒）。ウイルスの黒いドットが 3〜6個、外へ飛ぶ（「ウイルスがはがれる」）。

### 1-4. アプリごとの「当たった絵」の決まり

- スキンごとに、次の4つを決める（各章の「当たった絵」）。
  1. **当たった絵**：プレイヤーの能力が敵に当たったとき。そのアプリの「うまくいった・処理した」の UI（チェック・既読・選択の枠など）。

  3. **エラーの絵**：敵の攻撃がプレイヤーに当たったとき。そのアプリの「エラー・困った」の UI（エラーの赤丸・クラッシュしたタブ・通知バッジなど）。
  4. **通知の題名**：とどめのときの隅の通知（1-5）。
- 色：当たった絵は、アプリの色（`AppTheme` の代表の色）＋白。エラーの絵は、赤 `#FF453A`＋白＋そのアプリの地の色。

### 13-2. 技ごとに足す物

- **エラー弾**（VS Code の物を残している）：Dev のスキンではなく、赤い字の札 `ERR!`（22×9ドット。黒い地に赤い字、後ろに四角いカーソルの残像 2個）。着地の赤い波線は、赤い `^^^^^^`（コンパイラのエラーの印）にする。
- **sudo rm -rf /floor**（4-1）：くずれる区画の上に、灰色の小さい行（`rm: floor/01` の形の棒。字でなく棒でよい）が、下から上へ速く流れる（0.3秒）。戻るとき、区画の上に緑の `[ OK ]`。
- **chmod 000 player**（4-2）：南京錠の上に、3つの字 `r` `w` `x`（緑、各 6ドット）。**鎖が下りる 0.9秒の間に、0.3秒ごとに1字ずつ赤い `-` に変わる**（`rwx` → `-wx` → `--x` → `---`）。`---` になった瞬間が判定。秒数は今のまま（予告の残り時間が字で見える）。
- **fork() &**（4-3）：分身が出る瞬間、ボスの絵が横に 2つ → 4つに「割れる」（0.15秒。うすい緑の像が左右へ分かれて、分身の位置へ飛ぶ）。分身の弾 `&` が当たったら、エラーの絵 `Killed`。
- **文字列の雨**：先頭の1字だけ白、その後ろは緑がだんだん暗くなる（3段）。床に着いたら、字が左右へ 2個ずつはねる。
- **sudo reboot**（4-4）：今のまま。
- 今 → 変化：当てるたびに `[ OK ]` が積まれる。chmod の残り時間が `rwx` で見える。とどめが `[Process completed]`。

## 14. 作る順番と、実装担当の分け方

### 14-1. ぶつからないための決まり

- **共通のファイルは、共通担当（担当1）だけが直す。**
  - `AttackData`・`AttackRunner`・`Projectile`・`AreaStrike`・`FallingObject`・`Hitbox`・`DamageInfo`・`Health`・`VirusGauge`・`StageCamera`・`StageDirector`・`AbilityForge`（`AppVisuals.cs`）・`SkillDefinition`・`EffectKit.cs`。
- **だれも直さない物**：攻撃データなどのアセット、作成ツール（`BossTestSceneBuilder`・`AbilitiesBuilder`・`ArtAssets`・`AppBossSkillsBuilder`）、`Tools/art/gen_sprites.py`、絵のファイル。
  - 枠は攻撃データの名前から決める。絵はコードの中のドット絵。だから、アセットを作り直さなくてよい。
- **ほかの担当は、新しいファイルを足すだけ**（1スキン＝1ファイル。`FinderArt` の作り方）。置き場【仮】：`Assets/Scripts/Visual/Skins/`。
  - `Vfx.cs`・`PlayerVfx.cs` も担当1（近接の火花を 1-4 の絵に替える。新しいタブは、スキンのワープの枠を呼ぶ形にして、絵は担当2 が自分のファイルに書く）。
  - **この一覧に無い今あるファイルを直したくなったら、担当1 に頼む**（`PlayerSkillExecutor`・`BossController`・`BossArmorVisual`・`DamageBlink` など）。
- 例外（持ち主を1人に決める）：
  - `WarpTelegraph`・`LockOnStrike` → 担当2。
  - `Combat/Custom/Finder/`・`Combat/Custom/Premiere/` → 担当4。
  - `Combat/Custom/Terminal/`・`Boss/Terminal/` → 担当1。
- スキンが無い・枠が無いときは、今の見た目のまま。**途中のどの時点でも、ビルドが通って遊べる。**

### 14-2. 最初の2〜3時間（担当1 が先に作って、形を固める）

1. スキンの一覧と枠の一覧（1-1）。アプリ → スキンの表。攻撃データの名前 → 枠の表。
2. スキンの入口（`Dress`・`Hit`）と、場面（予告・本体・着地・消える）の知らせ。中身が空でも動くこと。
3. 当たった情報にスキンを足す。当たったエフェクトの部品（1-2）を、Generic の絵で出す。
4. ヒットストップとゆれの入口（1-3）。
- この間、担当2〜4は、自分のスキンの絵（ドット絵の並び）と、1-1 の形に合わせた中身を、新しいファイルに書き始めてよい。入口の名前は、担当1が最初に決めて知らせる。

### 14-5. 確かめること（実装担当）

- スキンをかける前と後で、当たり判定の位置・大きさ・秒数が同じこと（技の仕様の「OK の条件」は、そのまま通ること）。
- 敵の攻撃は赤いふち、プレイヤーの攻撃は白いふちで、白黒の画面にしても見分けられること。
- ロックオン 9本・塗り・残る床で、ヒットストップが重ならないこと（1秒に 0.2秒まで）。
- 暗転・デスクトップの画面・再起動の演出の間に、時間の速さが変にならないこと。
- 形態変化（50%）と正常化（100%）で、スキンの足した絵が全部消えること。
- 自動の撮影（ビルドしたゲーム）で、Chrome・VS Code・代用ボス1体・Terminal を撮って、まさぴ〜に見せる。

## 15. 【要相談】まさぴ〜・チームに聞くこと

1. **敵の攻撃の色**：「今の実装」14章の【確定】「敵の攻撃は赤系のまま」を、「中はアプリの形と色、ふちと予告は赤」に言い直した（0-3）。全部を赤にすると、どのアプリの技か分からなくなるため。能力ブレークポイントの赤丸だけは、プレイヤーの物でも赤（3-6）。
2. **ヒットストップ**：見た目だけの仕様だが、ゲームの時間が一瞬（0.05〜0.12秒）止まる。当たり判定・ダメージは変わらない。技の秒数は、止まった分だけ実時間で伸びる。入れてよいか。
3. **ポップアップを少しずつずらして出す**（2-3 のハッタリ）：絵だけをずらす。判定の瞬間は変えない。絵と判定が最大 0.15秒ずれるので、いやなら同時にする。
4. **実在の UI の文言・絵**：`Aw, Snap!`（クラッシュしたタブ）、虹色の待ちカーソル、`[Process completed]`、`Not Responding`。ロゴではないが、本物とほぼ同じ。パロディとして使ってよいか。だめなら `Oops!`・灰色の輪・`done` などに変える。
5. **⏸ の印**（能力ブレークポイントが当たった相手）：のけぞりの間だけ出す飾り。「長く止まる」と思わせるなら、やめる。
6. **数字を出す飾り**：Game のコンボの数（`x2`…）、Chat の赤いバッジ（受けた回数）、棒グラフの `120%`、スローの `50%`。「説明の文章は出さない」の決まりの外にある UI のまねとして入れた。数字が説明に見えるなら、外す（形だけにする）。
7. **隅の通知**：とどめのときだけ、題名1行（1-5）。「説明のバナーは出さない」の決まりに当たるなら、アイコンだけの板にする。
8. **代用ボスの技の見た目を、アプリの種類ごとに変える**（1-1）：動きは Chrome・VS Code の技のまま。Slack のボスは吹き出しと通知バッジで、Excel のボスはグラフで攻撃して見える。アプリ → スキンの表（設計メモ9章の名前）を新しく持つ。表の中身（どのアプリがどのスキンか）を、チームで見てほしい。
