# 音のデータの形式（SE・BGM・割り当て）

2026-11-19。このゲームの音は、全部 Python（numpy）で一から作る（フリー素材・本物のアプリの音は使わない）。
音のもと（このフォルダの JSON）→ `python3 Tools/audio/build_audio.py` → `Assets/Resources/Audio/SE/*.wav`・`Assets/Resources/Audio/BGM/*.wav`。
割り当て（どの技・どの出来事でどの SE を鳴らすか）は `Assets/Resources/Audio/Maps/*.json`（Unity が読む）。

```
Tools/audio/
  FORMAT.md            この文書（決まり）
  synth/               音を作るプログラム（Opus 担当）
  build_audio.py       全部を作り直して Assets へ書き出す
  check_audio.py       割り当てと音のファイルが合っているか調べる
  se/*.json            SE のレシピ（Fable 担当。ファイルは担当ごとに分ける）
  bgm/*.json           BGM・ジングルの楽譜（Fable 担当。1曲1ファイル）
Assets/Resources/Audio/
  SE/<id>.wav          44100 Hz・モノラル・16bit
  BGM/<id>.wav         32000 Hz・モノラル・16bit（ループの本体）
  BGM/<id>_intro.wav   イントロがある曲だけ（1回だけ流して、本体のループへつなぐ）
  Maps/*.json          割り当て（担当ごとにファイルを分ける。Unity が全部まとめて読む）
```

共通の決まり
- id は英小文字・数字・`_` だけ。SE は `se_` で始める。BGM は `bgm_`、ジングル（1回だけ流れる短い曲）は `jingle_` で始める。
- **本物のアプリの通知音・起動音・効果音をまねしない**（Mac の起動音、Slack のノック音、LINE の通知音、Discord の入退室音、iMessage の送信音、Teams・Zoom の着信音、Windows の音、ゲーム機の音など）。ロゴと同じで、音色・リズムの雰囲気だけ寄せて、メロディや音そのものは自分で作る。
- 実在のゲーム・アニメの曲のメロディを使わない（「〜っぽい」雰囲気まで）。
- 見た目はドット絵のレトロ風なので、音も **チップチューン（ファミコン風の矩形波・三角波・ノイズ）を中心** にする。必要なら sine・saw も使ってよい。

## 1. SE のレシピ（`Tools/audio/se/<担当>.json`）

```json
{
  "sounds": [
    {
      "id": "se_example_ping",
      "desc": "何の音か・元ネタ（日本語で短く）",
      "peak": 0.85,
      "layers": [
        { "wave": "pulse", "duty": 0.25, "at": 0.0,
          "notes": [["E6", 0.05], ["B6", 0.09]],
          "env": {"a": 0.002, "d": 0.05, "s": 0.4, "r": 0.04}, "vol": 0.8 },
        { "wave": "noise", "at": 0.0, "freq": 6000, "freq_end": 1500, "dur": 0.08, "curve": "exp",
          "env": {"a": 0.0, "d": 0.08, "s": 0.0, "r": 0.0}, "vol": 0.3 }
      ],
      "fx": {"lp": 9000, "hp": 80, "crush": 0, "echo": [0.09, 0.3, 0.25]}
    }
  ]
}
```

音（sound）
| キー | 意味 | 省略したとき |
|---|---|---|
| `id` | ファイル名（`SE/<id>.wav`） | 必須 |
| `desc` | 説明（日本語） | 必須 |
| `peak` | 出来上がりの一番大きい所をこの大きさにそろえる（0〜1） | 0.85 |
| `layers` | 重ねる音の層（1つ以上）。全部足してから `fx` をかける | 必須 |
| `fx.lp` / `fx.hp` | ローパス・ハイパス（Hz。1次のフィルター） | なし |
| `fx.crush` | ビットを落とす（4〜8。0 でなし）。ザラザラさせる | 0 |
| `fx.echo` | `[遅れ秒, 戻りの割合 0〜0.8, 混ぜる割合 0〜1]` | なし |
| `fx.reverse` | true で全体を逆再生にする（吸い込む音など） | false |

層（layer）
| キー | 意味 | 省略したとき |
|---|---|---|
| `wave` | `square`・`pulse`・`triangle`・`saw`・`sine`・`noise`（ザー）・`noise_tonal`（ファミコンの短い周期のノイズ。金属っぽい） | 必須 |
| `at` | 始まる時刻（秒） | 0 |
| `notes` | `[[音名, 長さ秒], ...]`。音名は `C0`〜`B8`、`#` と `b` 可（`C#5`・`Eb4`）。`"r"` は休み。数字（Hz）でもよい | — |
| `freq` / `freq_end` / `dur` / `curve` | `notes` の代わりに、周波数を `freq` から `freq_end` へ `dur` 秒で動かす。`curve` は `exp`（音程として自然）か `lin` | `freq_end`=`freq`、`curve`=`exp` |
| `duty` / `duty_end` | パルスの幅（0.125・0.25・0.5 など）。`pulse` だけ。時間で動かせる | 0.5 |
| `vib` | ビブラート `[深さ（半音）, 速さ Hz]` | なし |
| `arp` / `arp_rate` | アルペジオ。`arp` は半音のずれの列（例 `[0, 4, 7]`）、`arp_rate` 秒ごとに次へ | なし |
| `env` | `a` 立ち上がり秒・`d` 減る秒・`s` 保つ大きさ（0〜1）・`r` 離した後の余韻秒。`notes` では音ごと、スイープでは `dur` 全体にかかる | `{a:0.002,d:0.05,s:0.7,r:0.03}` |
| `vol` | この層の大きさ（0〜1） | 0.7 |
| `repeat` / `repeat_gap` | この層を `repeat` 回くり返す（間隔 `repeat_gap` 秒）。`repeat_decay` で回ごとに小さく（0〜1） | 1 回 |

- ノイズの `freq` は「ノイズの細かさ」（高いほどシャー、低いほどゴー）。
- 音の長さは、層の終わり（余韻とエコーを含む）まで自動で決まる。後ろの無音は切る。
- SE は短く。ふつう 0.05〜0.6 秒、長くても 1.5 秒（ボスの大技の溜め・ステージの出来事など）。
- 何度も鳴る音（弾・当たり）は短く軽く。大技は太く。プレイヤーの音はボスの音とはっきり違う色にする（プレイヤー＝明るい・高め、ボス＝低め・濁り）。

## 2. BGM・ジングルの楽譜（`Tools/audio/bgm/<id>.json`）

16分音符のマス目に音を並べる、トラッカー風の書き方。

```json
{
  "id": "bgm_example",
  "desc": "どの画面の曲か・雰囲気（日本語）",
  "bpm": 120,
  "steps_per_beat": 4,
  "beats_per_bar": 4,
  "swing": 0.0,
  "instruments": {
    "lead":  {"wave": "pulse", "duty": 0.25, "env": {"a": 0.005, "d": 0.12, "s": 0.55, "r": 0.06}, "vol": 0.32, "vib": [0.15, 5.5, 0.15]},
    "harm":  {"wave": "pulse", "duty": 0.125, "env": {"a": 0.002, "d": 0.06, "s": 0.3, "r": 0.03}, "vol": 0.18, "arp_rate": 0.045},
    "bass":  {"wave": "triangle", "env": {"a": 0.002, "d": 0.05, "s": 0.9, "r": 0.03}, "vol": 0.45},
    "drums": {"kit": "chip", "vol": 0.5}
  },
  "patterns": {
    "lead_a": "C5 - - . E5 - G5 - | A5 - - - G5 - E5 . | F5 - E5 - D5 - C5 - | D5 - - - - - . . |",
    "harm_a": "C4+E4+G4 - - - - - - - | F4+A4+C5 - - - - - - - | Dm | ...",
    "bass_a": "C3 . C3 . G2 . C3 . | F2 . F2 . C3 . F2 . | ...",
    "drum_a": "k . h . s . h . | k . h k s . h h |"
  },
  "sections": {
    "A": {"bars": 4, "lead": "lead_a", "harm": "harm_a", "bass": "bass_a", "drums": "drum_a"},
    "B": {"bars": 4, "lead": "lead_b", "bass": "bass_a", "drums": "drum_a"}
  },
  "intro": ["I"],
  "loop": ["A", "B", "A", "C"],
  "jingle": false
}
```

全体
| キー | 意味 | 省略したとき |
|---|---|---|
| `bpm` | 速さ | 必須 |
| `steps_per_beat` | 1拍のマスの数（4 なら 16分音符） | 4 |
| `beats_per_bar` | 1小節の拍の数 | 4 |
| `swing` | 裏のマスを遅らせる割合（0〜0.5） | 0 |
| `intro` | 1回だけ流す区間の並び（`<id>_intro.wav` に書き出し） | なし |
| `loop` | くり返す区間の並び（`<id>.wav`。最後から最初へ切れ目なくつながるように作る） | 必須（ジングル以外） |
| `jingle` | true なら `loop` を1回だけ流して終わる（余韻をつけてフェードアウト） | false |
| `master` | `{"lp": Hz, "hp": Hz, "gain": 0〜1}` | なし |

楽器（instrument）
- ふつうの楽器：`wave`（SE と同じ）・`duty`・`env`・`vol`・`vib`（`[深さ半音, 速さHz, かかり始める秒]`）・`octave`（オクターブずらす整数）・`detune`（セント。もう1本少しずらして重ねる）・`arp_rate`（和音のマスを、同時に鳴らさず、この秒ごとに速く回すアルペジオにする。0 か省略で同時に鳴らす）・`echo`（`[遅れのマス数, 戻り 0〜0.8, 混ぜる 0〜1]`）・`lp`/`hp`。
- ドラム：`{"kit": "chip", "vol": 0.5}`。ノイズと三角波で作るファミコン風のドラム。

パターン（1文字列 = 1つの楽器の何小節か）
- マスは空白で区切る。`|` は小節の区切り（書かなくてもよいが、書くと1小節のマスの数を調べる）。
- `C5`・`F#4`・`Bb3`：その音を鳴らす。`C4+E4+G4`：和音（`arp_rate` があればアルペジオ）。
- `-`：前の音をのばす。`.`：音を止める（余韻に入る）。
- 後ろに `!` で強く（×1.3）、`'` で弱く（×0.6）。例 `C5!`・`h'`。
- ドラムのマス：`k` キック・`s` スネア・`h` クローズドハイハット・`o` オープンハイハット・`c` クラッシュ・`t` ロータム・`m` ミッドタム・`p` クラップ・`b` ベルのような金属音・`.` なし。`k+h` で重ねる。
- パターンが区間の `bars` より短ければ、くり返して埋める。長ければ切る。
- 区間に書かない楽器は、その区間は鳴らない。

決まり
- ループの本体は **24〜48 秒** くらい（ファイルの大きさのため）。ジングルは 2〜6 秒。
- ループはちょうどの小節数で終わること（最後の小節の余韻は、最初の頭に重ねて切れ目をなくす。プログラムがやる）。
- 音量の目安：メロディ 0.25〜0.35、ベース 0.35〜0.5、ドラム 0.4〜0.55。最後に全体を同じ大きさにそろえるので、楽器どうしのバランスだけ考えればよい。

## 3. 割り当て（`Assets/Resources/Audio/Maps/<担当>.json`）

Unity の JsonUtility で読むので、**辞書ではなく配列** で書く。担当ごとにファイルを分け、Unity は全部を読んでまとめる（同じキーが2つあれば、後に読んだ方。ファイル名の順）。

```json
{
  "moves": [
    {"move": "Attack_Slack_Channel_P1", "start": "se_slack_charge", "release": "se_slack_mention", "vol": 1.0, "pitch": 1.0},
    {"move": "Attack_Slack_Channel_P2", "start": "se_slack_charge", "release": "se_slack_mention", "vol": 1.0, "pitch": 0.9}
  ],
  "events": [
    {"key": "player_jump", "se": "se_player_jump", "vol": 0.6}
  ],
  "fallbacks": [
    {"team": "Enemy", "kind": "Projectile", "start": "", "release": "se_enemy_shot", "vol": 0.7}
  ]
}
```

- `moves`：技（AttackData の名前 = アセットの名前）ごと。`start` は技を始めたとき（溜め・予告）、`release` は技が出た瞬間（弾が出る・落ちる・予告が攻撃に変わるなど。連射ではそのたび鳴る）。空文字なら鳴らさない。`vol`（0〜1.5）・`pitch`（0.5〜2）は省略で 1。
- ボスの技もプレイヤーの能力の技も、同じ `moves` に書く（プレイヤーの能力は `Skill_*` が使う `Attack_*` の名前で書く）。
- `events`：技以外の出来事。キーは下の表から選ぶ（Unity 側がその出来事のときに鳴らす）。
- `fallbacks`：`moves` に無い技（雑魚の攻撃など）の、陣営（`Player`/`Enemy`）× 種類（`Projectile`・`Area`・`Spawn`・`Warp`・`LockOn`・`Custom`）ごとの音。
- 鳴らしすぎ対策（同じ音は 0.06 秒あけ、同時に3つまで、ピッチを少しばらす）は Unity 側がやる。

## 補足（実装で決めたこと）

2026-11-19、`synth/` を作るときに、上の表だけでは決まらなかった所をこう決めた。

SE
- `noise` の `freq` は「LFSR を1秒に何回進めるか」（細かさ。6000 ならやや暗いザー、20000 以上で明るいシャー）。
- `noise_tonal` の `freq`・`notes` は **金属っぽい音の高さ**（短いモードは 93 ステップで1周するので、93 倍の速さで回す）。`A5` と書けば 880 Hz の金属音になる。
- `duty_end` は層の全体（`notes` なら全部の音の合計の長さ、スイープなら `dur`）でまっすぐ動く。
- `repeat_gap` は「前の回のゲートが終わってから、次の回が始まるまでの休み」（余韻は数えない）。省略・0 なら続けて鳴る。
- `repeat_decay` は回ごとに ×(1 − repeat_decay)。0 で小さくならない、0.3 なら 1・0.7・0.49…。
- `notes` の `"r"` は休み。3つ目に数字を書くとその音の大きさの倍率（`["C5", 0.1, 0.5]`）。`freq`・`freq_end` に音名を書いてもよい。
- `vib` は SE でも3つ目（かかり始める秒）を書ける。始める秒があると 0.08 秒かけて深くなる。
- ADSR：立ち上がりはまっすぐ、減る・余韻は始めが速い曲線。余韻は最低 2ms（`r: 0` でもプツッと鳴らない）。ゲートが a+d より短いときは、その時の大きさから余韻に入る。
- パルスは直流を引いてある（幅が狭いほど、とがった所が大きくなる。上下の幅はどの duty も同じ）。
- fx の順番：ハイパス → ローパス → `crush` → `echo` → 後ろの無音を切る → `reverse` → 頭 1ms フェードイン → -60dBFS より小さい後ろを切って 6ms フェードアウト → 一番大きい所を `peak` にそろえる。
- `crush` は、その時の一番大きい所を基準にビットを落とす（音量に関係なく同じザラザラ）。
- `echo` は「元の音 + 混ぜる割合 × エコー」。エコーが -60dB になるまで音を自動でのばす（最大 4 秒）。

BGM
- 楽器の名前は自由（`blip`・`pad` など）。`kit` が無い楽器は全部ふつうの楽器。`vol` の省略は 0.5。ふつうの楽器にも `duty_end` が使える（音ごとに動く）。
- `!`・`'` は `+` の1つずつにつく：`k+h'` はハイハットだけ弱い。和音を全部強くするなら `C4!+E4!+G4!`。`!!` のように重ねてもよい。
- `-` が区間の頭にあれば、前の区間の音をそのままのばす（鳴っている音が無ければ休み）。ドラムは `-`・`.` を無視する（1回鳴らすだけ）。
- `|` を書いたパターンは、全部の小節のマスの数を調べる（頭と最後の `|` はあってもよい）。`|` が無いパターンは長さ自由で、区間の長さまでくり返す。上の 2章の例は書き方の見本で、そのままでは小節のマスが足りない（`Dm`・`...` も読めない）。
- マスに数字を書くと Hz（`440`）。
- `arp_rate` が無い和音は、同時に鳴らして1音ずつ ×1/√(音の数)。`detune` は元の音とずらした音を ×0.7 ずつ重ねる。
- `swing` は奇数番目のマス（裏）を「マスの長さ × swing」だけ遅らせる。
- `master.lp`/`hp` はそろえる前にかけ、`master.gain` は **そろえた後** にかける（一番大きい所 = 0.9 × gain。静かな曲用）。
- ループの各回の頭は整数のサンプルにそろえる。長さは「小節数 × 1小節の秒 × 32000」を四捨五入（ちょうどとの差は 1 サンプル未満）。ドラムのノイズはマスの位置で決まるので、2回目のループは3回目と同じ音になる（最後から最初へぴったりつながる）。
- イントロ（`<id>_intro.wav`）は、ループの頭に重なる余韻は入らず、ちょうど区切りで切れる。イントロとループは同じ倍率でそろえる。
- ジングル：（`intro` があればイントロ＋）`loop` を1回 → 1.5 秒の余韻を cos² でフェードアウト → 後ろの無音を切る。
- 区間に `bars` が無いときは、いちばん長いパターンの小節数にする（注意を出す）。

作る・調べる
- `build_audio.py --prune` は消す WAV の `.meta` も一緒に消す。読めないデータのファイルがあるときは消さない。
- 全部の音の最後に 12 Hz のハイパス（直流取り。聞こえない）をかける。
- `--prune` は、SE か BGM のレシピが1つも無いときはそのフォルダを消さない（データの場所のまちがいで全部消さないように）。`--only` を使っても、残すものは全部のレシピから決める。
- `noise` の freq にかける倍率は `synth/core.py` の `NOISE_CLOCK_SCALE`（今は 1.0 = 上のとおり）。全体に暗すぎたら 2〜3 にして作り直す（ドラムは変わらない）。

## 4. ギミックの音（2026-11-19 追加：アプリごとのステージの決まり・ボスの仕掛け）

技の音（§3 の `moves`）とは別に、アプリごとの **ギミック**（ステージの決まり `StageRule`・場面③の出来事・Chrome/VS Code/Finder/Premiere/Terminal の仕掛け・Terminal の再起動とカーネルパニックなど）に、専用の SE を付ける。

- **キー**：`gm_<アプリ>_<瞬間>`（英小文字・数字・`_`）。アプリの名前は SE と同じ（`slack`・`line`・`chrome`・`vscode`・`finder`・`premiere`・`terminal`・`github`…）。例 `gm_slack_unread_add`・`gm_zoom_warning`・`gm_zoom_cut`。
- **鳴らし方**：コードのその瞬間に `GameAudio.Event("gm_…")` を1行入れる（Opus の担当が入れる）。割り当ては §3 の `events` と同じ形で、`Assets/Resources/Audio/Maps/4?_gimmick_<担当>.json` の `events` に書く（キーは上の `gm_` で始まる物。§3 の表に無くてよい）。同じキーは 0.06 秒あけて3つまで（Unity 側）。音の高さを変えたいとき（数が増えるたびに高く、など）は `GameAudio.Event(key, 倍率)`。
- **SE のレシピ**：`Tools/audio/se/gimmick_<担当>.json`。id は `se_gm_<アプリ>_<何>`。ギミックごとに専用の音を作る（そのアプリの技の音と同じ色にそろえるのはよい）。
- **鳴らす所の指示書**：`Tools/audio/hooks/gimmick_<担当>.tsv`（タブ区切り・1行目は見出し）：
  `key` ／ `file`（Assets/Scripts からの道） ／ `where`（クラス.メソッドと、どの文の直後か・どの条件のときか。コードの文をそのまま引用するとよい） ／ `note`（くり返しの間隔・ボスとプレイヤーどちらのときか・倍率の付け方など）
- 決まり：本物のアプリの音（Zoom の終了音・Spotify の広告の音・Steam の実績の音・Mac の通知音など）はまねしない。プレイヤーに不利なギミック（Claude の上限・Zoom の40分・メモの鍵・Spotify の広告など）は、来る前と来た時がはっきり分かる音にする。何度も起きる物は小さく短く。
